# AI1WM Telegram Backups

Плагин планирует экспорты All-in-One WP Migration (AI1WM), хранит состояние
последнего бэкапа и отправляет текстовые уведомления в Telegram.

> Плагин не отправляет архивы-файлы в Telegram. Для успешного экспорта он
> отправляет текст с именем, размером и ссылкой на архив.

## Требования

- WordPress 5.3 или новее.
- PHP-версия, поддерживаемая установленными версиями WordPress и AI1WM.
- Активный All-in-One WP Migration с доступными классом
  `Ai1wm_Export_Controller` и функцией `ai1wm_archive_file()`.
- Для уведомлений — Telegram-бот, его Bot Token и Chat ID.
- Для регулярного запуска — работающий WP-Cron либо настроенный системный cron,
  который вызывает `wp-cron.php`.

Плагин проверяет зависимости AI1WM и показывает предупреждение в админке, если
основной плагин не активен. Расширение Unlimited не обязательно, но без него
могут действовать ограничения бесплатной версии AI1WM.

## Установка

1. Поместите каталог `ai1wm-telegram-backups` в
   `wp-content/plugins/` WordPress.
2. В админке WordPress откройте **Плагины → Установленные**.
3. Активируйте **AI1WM Telegram Backups**.
4. Убедитесь, что активен All-in-One WP Migration.
5. Откройте **Настройки → AI1WM Telegram**.

При первой активации плагин создаёт настройки по умолчанию, если опция
`ai1wm_tg_settings` ещё не существует. Активация не включает автоматические
бэкапы по умолчанию.

## Настройки по умолчанию

| Настройка | Значение по умолчанию | Назначение |
|---|---:|---|
| Автоматические бэкапы (`enabled`) | Выключены | Включает регулярное расписание WP-Cron |
| Интервал (`interval_days`) | 4 дня | Допустимы 4, 5, 7, 14 или 30 дней |
| Telegram Bot Token (`bot_token`) | Пусто | Токен бота для Bot API |
| Chat ID (`chat_id`) | Пусто | Получатель уведомлений |
| Хранить (`keep_backups`) | 3 архива | Количество сохраняемых архивов этого плагина; `0` отключает очистку |
| Уведомлять о старте (`notify_start`) | Включено | Текстовое сообщение при старте |
| Уведомлять об успехе (`notify_success`) | Включено | Текстовое сообщение после успешного экспорта |
| Уведомлять об ошибке (`notify_error`) | Включено | Текстовое сообщение при ошибке экспорта |
| Исключать темы (`themes_exclude`) | Выключено | Передаёт AI1WM опцию `no_themes` |
| Исключать плагины (`plugins_exclude`) | Выключено | Передаёт AI1WM опцию `no_plugins` |
| Исключать медиафайлы (`uploads_exclude`) | Выключено | Передаёт AI1WM опцию `no_media` |

Настройки исключения влияют на состав архива, а не только на уведомление.
Если включить исключение, соответствующие файлы не должны попадать в экспорт.
Учитывайте это при планировании восстановления сайта.

## Первичная настройка

### 1. Создайте Telegram-бота

1. Откройте Telegram и найдите `@BotFather`.
2. Создайте нового бота командой `/newbot`.
3. Сохраните выданный Bot Token как секрет. Не публикуйте его и не добавляйте
   в репозиторий.

### 2. Получите Chat ID

1. В личном чате откройте созданного бота, нажмите **Start** и отправьте любое
   сообщение. Для группового чата добавьте бота и отправьте сообщение в группе.
2. На странице **Настройки → AI1WM Telegram** введите Bot Token и нажмите
   **Найти Chat ID**.
3. Если найден ровно один чат, плагин подставит его ID автоматически. Если
   найдено несколько чатов, выберите нужный ID из списка и введите его в поле.
4. Нажмите **Сохранить**, затем **Отправить тест в Telegram**.

Чат должен быть доступен именно этому боту. Нельзя использовать токен вместо
Chat ID. Метод обнаружения использует Telegram `getUpdates`; он может быть
недоступен, если для бота настроен webhook или обновления забирает другой
клиент.

### 3. Сохраните расписание и параметры экспорта

1. Установите флажок **Создавать бэкапы автоматически**, если нужен регулярный
   запуск.
2. Выберите интервал.
3. Настройте хранение архивов и параметры исключения.
4. Оставьте включёнными нужные уведомления.
5. Нажмите **Сохранить**.

После сохранения проверьте отображаемую дату следующего запуска и отправьте
тестовое сообщение. Тест проверяет доставку текста в Telegram, но не запускает
экспорт AI1WM.

### 4. Необязательно: задайте реквизиты в `wp-config.php`

Для серверной конфигурации можно определить константы до загрузки WordPress:

```php
define( 'AI1WM_TG_BOT_TOKEN', 'ваш-токен-бота' );
define( 'AI1WM_TG_CHAT_ID', 'идентификатор-чата' );
```

Если соответствующая непустая константа задана, значение берётся из неё, а
поле в админке блокируется. Константы имеют приоритет над сохранёнными
значениями. Не вставляйте реальные секреты в публичные файлы или Git.

## Использование

### Ручной бэкап

1. На странице настроек проверьте параметры формы.
2. Нажмите **Сделать бэкап сейчас** и подтвердите запуск.
3. Плагин сохранит переданные в форме настройки, синхронизирует регулярное
   расписание с флажком автоматических бэкапов и поставит отдельную одноразовую
   задачу в очередь с принудительным запуском.
4. Страница настроек должна открыться снова с сообщением о постановке задачи.
   Текущий статус и результат появятся после фактического запуска и завершения
   экспорта.

Ручной запуск работает и при выключенном флажке автоматического расписания.
Он не включает постоянное расписание. Однако одноразовая задача выполняется
через WP-Cron: если WP-Cron отключён или не работает loopback/system cron,
задача может ожидать его следующего запуска.

### Регулярные бэкапы

После включения флажка плагин создаёт периодическое WP-Cron событие. При
первой постановке первый запуск планируется примерно через час, дальнейшие
запуски повторяются с выбранным интервалом. Если изменить интервал, расписание
пересоздаётся.

Доступны интервалы: 4, 5, 7, 14 и 30 дней.

### Статус

На странице плагина показываются:

- последний статус (`running`, `success` или `failed`);
- время последнего обновления статуса;
- имя последнего архива и его размер, если известны;
- сообщение о последнем результате;
- время следующего регулярного запуска, если он запланирован.

Это краткое состояние, а не история всех запусков: новые результаты
перезаписывают прежние.

## Расписание и WP-Cron

WP-Cron проверяется во время запросов к сайту и не является системным
планировщиком с гарантированным временем запуска. При малой посещаемости
регулярное событие может выполниться позже. Если в `wp-config.php` установлено
`DISABLE_WP_CRON`, настройте системный cron или иной поддерживаемый механизм,
который регулярно вызывает `wp-cron.php`.

Пример команды для системного cron (путь и частоту следует согласовать с
хостингом):

```sh
wget -q -O - https://example.com/wp-cron.php >/dev/null 2>&1
```

Используйте HTTPS и правильный адрес сайта. Не запускайте команду буквально
с `example.com`.

## Уведомления и хранение архивов

- Все сообщения — текстовые. Отправки `.wpress` файла в Telegram нет.
- Для успешного экспорта сообщение содержит сайт, имя архива, размер и ссылку,
  формируемую плагином.
- Каталог хранения определяется AI1WM; retention плагина удаляет только файлы,
  оканчивающиеся на `-tg.wpress`.
- Если `keep_backups` равен `3`, после успешного экспорта плагин старается
  оставить три самых новых архива с этим суффиксом. Значение `0` отключает
  автоматическое удаление.
- После успешного экспорта плагин проверяет все `*.wpress` в каталоге AI1WM.
  Если их пять или больше, он отправляет предупреждение с количеством и
  суммарным размером. Это предупреждение не имеет отдельного переключателя и
  может отправляться при каждом успешном запуске, пока число файлов остаётся
  выше порога.

## Безопасность

**Ссылка на архив требует особого внимания.** Успешное сообщение содержит
ссылку, собранную из фиксированного пути `/wp-content/ai1wm-backups/`. Она может
не соответствовать фактическому каталогу AI1WM. Если архив доступен веб-серверу
по прямому URL, получивший ссылку может скачать полный бэкап сайта. Не
пересылайте такую ссылку неавторизованным лицам; проверьте доступность архива
снаружи и настройки сервера. Для production предпочтительнее закрытое хранилище
или авторизованный endpoint, чем публичный URL.

Bot Token хранится в `wp_options`, если он задан через форму, и не шифруется
плагином. Для чувствительных установок используйте серверную конфигурацию,
ограничивайте доступ к БД и резервным копиям `wp-config.php`, не включайте
секреты в логи и репозиторий. Telegram Bot API включает токен в URL исходящего
запроса, поэтому убедитесь, что HTTP-логи и APM не сохраняют URL с секретом без
маскирования.

Действия в админке требуют capability `manage_options` и проверяют nonce.
Не предоставляйте доступ к этой странице пользователям, которым нельзя
управлять резервными копиями или Telegram-реквизитами.

## Устранение неполадок

### Не пришло тестовое сообщение

- Проверьте Bot Token и Chat ID.
- Напишите боту `/start` либо добавьте его в группу и отправьте там сообщение.
- Проверьте, что бота не удалили из чата и он имеет право отправлять сообщения.
- Повторите **Найти Chat ID**, если у бота нет настроенного webhook.
- Учитывайте, что тест отправляет только текст, а не архив.

### Ручной бэкап поставлен в очередь, но не стартует

- Проверьте, что WP-Cron WordPress не отключён или настроен системный cron.
- Убедитесь, что loopback-запросы сайта не блокируются хостингом, firewall,
  Basic Auth или плагином безопасности.
- Проверьте состояние WP-Cron и журнал PHP/WordPress.
- Подтвердите, что AI1WM активен и совместим с текущей версией плагина.

Сообщение о постановке в очередь означает, что задача поставлена, но не
гарантирует успешное завершение экспорта.

### Нет регулярных запусков

- Проверьте флажок **Создавать бэкапы автоматически**.
- Проверьте дату следующего запуска на странице настроек.
- Настройте системный cron для production-сайта и проверьте выполнение
  `wp-cron.php`.
- Убедитесь, что расписание не было удалено сторонним плагином или хостингом.

### В админке не работает страница плагина

- Убедитесь, что All-in-One WP Migration активен.
- Проверьте PHP error log и журнал WordPress.
- Проверьте, что текущий пользователь имеет `manage_options`.
- После обновления PHP/WordPress проверьте совместимость версий плагинов.

## Структура кода

### Файлы верхнего уровня

- `ai1wm-telegram-backups.php` — заголовок WordPress-плагина, версия и минимальная
  версия WordPress, константы путей/опций/cron-hook, подключение классов и
  регистрация обработчиков активации, деактивации и `plugins_loaded`.
- `README.md` — эта инструкция пользователя и карта исходного кода.

### Каталог `includes/`

- `class-admin.php` — административный интерфейс:
  - добавляет страницу **Настройки → AI1WM Telegram**;
  - обрабатывает действия формы `save`, `test`, `detect`, `run`;
  - проверяет права пользователя и nonce;
  - отображает состояние бэкапа и уведомления;
  - перед ручным запуском сохраняет настройки и ставит одноразовую задачу.
- `class-backup.php` — взаимодействие с экспортом AI1WM:
  - проверяет доступность зависимостей;
  - формирует параметры экспорта и отображение `backup_options` в
    `no_themes`, `no_plugins`, `no_media`;
  - обрабатывает запуск, успешное завершение и ошибку;
  - обновляет состояние, запускает retention и формирует Telegram-сообщения;
  - предупреждает о пяти и более архивах в каталоге AI1WM.
- `class-cron.php` — расписание:
  - регистрирует интервалы 4/5/7/14/30 дней;
  - создаёт, обновляет и очищает регулярное событие;
  - ставит ручной принудительный запуск как одноразовое событие WP-Cron.
- `class-plugin.php` — связывает классы с WordPress hooks:
  - регистрирует cron-hook и события окончания/ошибки экспорта AI1WM;
  - готовит настройки и расписание при активации;
  - удаляет задачи при деактивации.
- `class-settings.php` — настройки и статус:
  - значения по умолчанию;
  - загрузка, проверка и сохранение настроек;
  - чтение токена/Chat ID из констант `wp-config.php`;
  - сохранение последнего состояния экспорта;
  - нормализация Chat ID.
- `class-telegram.php` — Telegram Bot API:
  - отправка текстового сообщения через `sendMessage`;
  - поиск чатов через `getUpdates`;
  - форматирование имени чата;
  - разбор ошибок API и подсказка для `chat not found`.

## Важные настройки и точки расширения

Основные константы определяются в `ai1wm-telegram-backups.php`:

| Константа | Назначение |
|---|---|
| `AI1WM_TG_VERSION` | Версия плагина |
| `AI1WM_TG_FILE` | Путь к основному PHP-файлу |
| `AI1WM_TG_PATH` | Путь к каталогу плагина |
| `AI1WM_TG_URL` | URL каталога плагина |
| `AI1WM_TG_CRON_HOOK` | Имя cron-события запуска бэкапа |
| `AI1WM_TG_OPTION` | Ключ настройки в `wp_options` |
| `AI1WM_TG_STATE` | Ключ состояния последнего бэкапа в `wp_options` |
| `AI1WM_TG_BOT_TOKEN` | Необязательный серверный Telegram Bot Token |
| `AI1WM_TG_CHAT_ID` | Необязательный серверный Telegram Chat ID |

Ключевые WordPress hooks, регистрируемые классом `Ai1wm_Tg_Plugin`:

- `cron_schedules` — интервалы WP-Cron.
- `AI1WM_TG_CRON_HOOK` (`ai1wm_tg_run_backup`) — запускает `Ai1wm_Tg_Backup::run`.
  Для ручного задания передаётся аргумент `true`, разрешающий запуск при
  выключенном регулярном расписании.
- `ai1wm_status_export_done` — обработка успешного экспорта.
- `ai1wm_status_export_error` — обработка ошибки экспорта.
- `admin_init` — синхронизация регулярного расписания с настройками.

Имена архивов этого плагина получают суффикс `-tg.wpress`. Настройки и
состояние хранятся в `wp_options`; отдельные таблицы БД плагин не создаёт.

## Известные ограничения

- Синтаксическая проверка PHP не заменяет тест на работающем WordPress.
- WP-Cron зависит от вызовов сайта или настроенного системного cron.
- Ошибки автоматической доставки Telegram-сообщений сейчас не всегда
  сохраняются/показываются в админке.
- Прямую ссылку на архив и фактическую доступность файла нужно проверить для
  конкретного каталога AI1WM и веб-сервера.
- Ручной запуск ставится в очередь; успешная постановка не равна успешному
  завершению бэкапа.
